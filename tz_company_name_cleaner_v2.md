## 1. ОБЩЕЕ ОПИСАНИЕ

Titan Cleaner — портативное GUI-приложение для **анонимизации и деанонимизации** документов. Заменяет персональные данные, названия компаний, реквизиты на английские псевдонимы с возможностью полного обратного восстановления. Работает с флешки как единый .exe без установки Python.

**ВАЖНО: Текст никогда не удаляется — только заменяется.** Удаление текста ломает структуру документов, сбивает форматирование и нарушает целостность таблиц.

### Ключевые возможности:
- **Анонимизация** — замена ФИО, организаций, городов, реквизитов, контактов на английские псевдонимы
- **Деанонимизация** — обратная замена из SQLite базы, даже если документ переработан ИИ
- **Автодетект** — автоматический поиск 14 типов персональных данных
- **Трёхколоночный UI** — настройки слева, листы документа по центру, правила замены справа
- **Страницы-листы** — все страницы документа в одном скролле с визуальными разделителями
- **Карта замен** — встроенная сворачиваемая таблица всех замен (авто + ручные) с цветовыми метками
- **Ручное добавление** — выделение текста мышкой → автовыбор следующей свободной замены → галочки занятых
- **SQLite база маппингов** — вся история замен, поиск по файлам, отдельный маппинг на каждый файл
- **14 типов сущностей** — ФИО, организации, города, ИНН, ОГРН, КПП, БИК, счета, СНИЛС, паспорт, телефоны, email, URL, адреса
- **3 формата документов** — .docx, .pdf, .xlsx
- **OCR для сканов** — Tesseract (портативный, в комплекте)
- **Английские псевдонимы** — 100 городов, 40 компаний, 100+ имён/фамилий, уникальные номера
- **Копирование текста** — Ctrl+C работает во всех текстовых полях приложения

### 4.2 Левая колонка — настройки и карта замен

- **ФАЙЛЫ** — список загруженных файлов, кнопки добавления/очистки
- **СВОДКА** — количество найденных сущностей по типам
- **PDF** — режим (текст/штамп), выбор штампа, OCR
- **РЕЗУЛЬТАТ** — папка вывода
- **ЛОГ** — результаты обработки
- **КАРТА ЗАМЕН** — сворачиваемая таблица всех замен с цветными метками:
  - Тип (Орг/ФИО/Город/...) цветом маркера
  - Оригинал → Замена
  - Источник: `[авто]` / `[ручн]`
- **ПРОГРЕСС** — индикатор выполнения

### 4.3 Центральная колонка — листы документа

- **Белый фон** с чёрным текстом — имитация документа
- **Все страницы в одном скролле** — визуальные разделители `━━━` между листами
- Заголовок `─── Страница N ───` на сером фоне
- Кнопки `← Пред.` / `След. →` — прокрутка к нужной странице
- Переключение между файлами — выпадающий список
- **Разбивка страниц DOCX** — по page breaks из документа, или авторазбивка по ~3000 символов
- **PDF** — каждая страница PDF = отдельный лист

### 4.4 Правая колонка — выделенное и правила

- **ВЫДЕЛЕННОЕ** — панель ручного добавления:
  - Выделенный текст из превью
  - Выбор типа (Организация / ФИО / Город / Своё)
  - Показ **занятых замен** для выбранного типа (N/M)
  - **Автовыбор следующей свободной** замены из пула
  - Кнопка «Добавить»
- **ПРАВИЛА ЗАМЕНЫ** — динамические поля:
  - Кнопки `+Орг` `+Город` `+ФИО подп.` `+ФИО уч.` `+Своё`
  - Каждое поле: искать → заменить на (выпадающий список)
  - **Галочки ✓** у занятых замен в выпадающем списке
  - Кнопка удаления ✕

### 4.5 Ручное добавление замен с мгновенной подсветкой

1. Пользователь видит незамеченное слово в тексте предпросмотра
2. Выделяет его мышкой
3. В правой панели «ВЫДЕЛЕННОЕ» появляется текст + информация о занятых заменах
4. Выбирает тип (Организация / ФИО / Город / Своё)
5. Нажимает «Добавить» → **автоматически выбирается следующая свободная замена**
6. **Маркер мгновенно появляется** на всех вхождениях в тексте
7. Карта замен и галочки обновляются
8. Entity добавляется в авто-результаты → будет обработан при нажатии ОБРАБОТАТЬ

### 4.6 Объединённая обработка

Кнопка ОБРАБОТАТЬ **всегда объединяет** ручные правила + авто-детект:
- Автодетект нашёл 28 сущностей
- Пользователь добавил мышкой ещё 3 пропущенных
- При обработке заменяются все 31

## 5. АНОНИМИЗАЦИЯ — АНГЛИЙСКИЕ ПСЕВДОНИМЫ

### 5.1 Принцип

Вместо очевидных заглушек (`[КОМПАНИЯ]`, `0000000`) используются правдоподобные английские аналоги. Это позволяет:
- Отправлять анонимизированный документ в ИИ для анализа
- ИИ воспринимает данные как реальные и даёт качественный анализ
- После анализа документ деанонимизируется обратно

### 5.2 Базы псевдонимов (`core/english_pseudonyms.py`)

| Тип | В базе | В выпадающем списке GUI | Примеры |
|-----|--------|------------------------|---------|
| Города | 100 | 30 | London, Manchester, Bristol, Cambridge |
| Компании | 40 | 30 | Northgate Industries Ltd, Meridian Solutions Corp |
| Мужские имена | 50 | — | James, John, Robert, Michael |
| Женские имена | 50 | — | Mary, Patricia, Jennifer, Linda |
| Фамилии | 100 | — | Smith, Johnson, Williams, Brown |
| ФИО подписант | — | 20 | J.A. Smith, R.M. Johnson, D.K. Williams |
| ФИО участники | — | 6 шаблонов | Employee #{n}, Staff Member #{n} |

## 6. ДЕАНОНИМИЗАЦИЯ

### 6.1 Принцип работы

1. При анонимизации маппинг `оригинал ↔ псевдоним` сохраняется в SQLite базу
2. Документ отправляется в ИИ для анализа (ИИ видит английские имена/компании)
3. ИИ может полностью переструктурировать документ
4. При деанонимизации — обратная замена по строкам из базы

Псевдонимы **выживают** любую реструктуризацию, потому что ИИ воспринимает их как реальные имена/названия.

### 6.2 SQLite база (`titan_cleaner.db`)

```sql
sessions
├── id (PK)
├── created_at
└── total_replacements

file_mappings
├── id (PK)
├── session_id (FK → sessions)
├── source_filename          -- исходный файл
├── output_filename          -- анонимизированный файл
├── created_at
└── total_replacements

mappings
├── id (PK)
├── file_mapping_id (FK → file_mappings)
├── original                 -- исходный текст
├── pseudonym                -- замена
└── entity_type              -- тип сущности
```

### 6.3 UI деанонимизации

- Кнопка «ДЕАНОНИМИЗАЦИЯ» (зелёная) в нижней панели
- Открывается панель с поиском по базе (по имени файла)
- Список файлов: #ID, имя файла, дата, количество замен
- Клик по файлу → предпросмотр маппинга (псевдоним ← оригинал)
- Выбор документа для деанонимизации (от ИИ или изменённый)
- Кнопка «ДЕАНОНИМИЗИРОВАТЬ» → обратная замена → результат

## 7. АВТОДЕТЕКТ СУЩНОСТЕЙ (`core/auto_detect.py`)

### 7.1 Поддерживаемые типы (14)

| Тип | Метод детекции |
|-----|---------------|
| ФИО (полное) | Regex: `Фамилия Имя Отчество` + база 400+ имён |
| ФИО (инициалы) | Regex: `Иванов А.В.` / `А.В. Иванов` — облегчённая проверка (без фильтра по окончанию) |
| ФИО (фамилия) | Морфология: окончания -ов/-ев/-ин/-ский + контекст |
| Организации | Regex: `ООО/ПАО/АО «Название»` + ИП + смешанные кавычки (`ООО ТП "Жопка"`) |
| Города | База 1100 городов + склонения + ё/е нормализация |
| ИНН | Regex: 10/12 цифр с меткой или без |
| ОГРН | Regex: 13/15 цифр |
| КПП | Regex: 9 цифр |
| БИК | Regex: 9 цифр |
| Банковские счета | Regex: 20 цифр (р/с, к/с) с меткой или без |
| СНИЛС | Regex: `000-000-000 00` |
| Паспорт | Regex: `серия 00 00 № 000000` |
| Телефоны | Regex: `+7 (000) 000-00-00` и вариации |
| Email / URL | Regex: стандартные паттерны + валидация доменов |

### 7.2 Защита от ложных срабатываний

- **Белый список организаций** (`whitelist.py`): ФНС, суды, министерства, Правительство — не заменяются
- **Ложные фамилии** (`FALSE_POSITIVE_SURNAMES`): 300+ слов (Январь, Строительный, и т.д.)
- **Контекстная проверка**: города только в адресных контекстах
- **ё/е нормализация**: Будённовск = Буденновск
- **Облегчённая проверка фамилий с инициалами**: инициалы — сильный сигнал, не требуется проверка окончания (поддержка нестандартных фамилий: Лейфрид, Прокопив и т.д.)
- **Защита от ложных адресов**: `б.` не считается сокращением бульвара (только `б-р` или `бульвар`)

### 7.3 Разбивка страниц DOCX

DOCX-документы разбиваются на страницы:
1. По **page breaks** из документа (`<w:br w:type="page"/>`, `<w:pageBreakBefore/>`)
2. Если page breaks нет — **авторазбивка** по ~3000 символов по границам абзацев
3. Таблицы добавляются к последней странице

### 8.1 DOCX (`core/docx_cleaner.py`)

- Склейка runs в параграфах (word разбивает текст на части)
- Позиционная карта: символ → (run_index, char_index)
- Замена с сохранением форматирования первого run
- Обработка: параграфы, таблицы, колонтитулы
- Дедупликация перекрывающихся совпадений (побеждает длиннейшее)

### 8.2 PDF (`core/pdf_cleaner.py`)

**Режим 1 — Текстовая замена:**
1. Поиск текста → `page.search_for()` → координаты
2. `page.add_redact_annot()` — закрашивание белым
3. `page.apply_redactions()` — удаление из потока
4. `fitz.TextWriter()` — наложение текста замены с кириллическим шрифтом

**Режим 2 — Графический штамп:**
1. Те же шаги 1-3
2. `page.insert_image()` — наложение PNG-штампа

**Шрифты:** DejaVuSans → LiberationSans → FreeSans → arial.ttf → calibri.ttf → fallback

**Штампы:** чёрная плашка (программно), ромашка, замок, конфиденциально, свой PNG

### 8.3 Excel (`core/xlsx_cleaner.py`)

- Обработка всех листов
- Пропуск формул (`=...`)
- Замена в строковых ячейках

### 8.4 OCR для сканов

- Tesseract (портативный, в комплекте)
- `ocr_page()` → рендер в PIL Image → распознавание → координаты слов
- Поддержка русского + английского языков

## 9. ПРАВИЛА ЗАМЕНЫ

### 9.1 Типы полей

| Тип поля | Поиск | Замена |
|----------|-------|--------|
| Организация | Regex: все вариации (падежи, кавычки, орг. формы, смешанные кавычки) | Статическая строка |
| Город | Regex: склонения + префиксы (г., город) | Статическая строка |
| ФИО подписант | SurnamePattern: инициалы + склонения | Статическая строка |
| ФИО участники | Список SurnamePattern + ReplacementMapper | Последовательная замена |
| Своё поле | Простой regex (escaped text) | Статическая строка |

### 9.2 ReplacementMapper

Гарантирует консистентность: одна фамилия = одна заглушка во всех файлах сеанса.

```python
mapper = ReplacementMapper("Employee #{n}")
mapper.get_replacement("Петров")    # → "Employee #1"
mapper.get_replacement("Сидорова")  # → "Employee #2"
mapper.get_replacement("Петров")    # → "Employee #1" (тот же!)
```

### 9.3 Склонение фамилий (`core/surnames.py`)

Поддержка окончаний: -ов, -ев, -ёв, -ин, -ын, -ский, -цкий (муж. и жен. формы).

```
Петров → Петров, Петрова, Петрову, Петровым, Петрове, Петровых
Петров И.С. → Петров И.С., И.С. Петров, И. С. Петров
```

## 14. ПРАВИЛА РАЗРАБОТКИ

- **GUI**: CustomTkinter, тёмная тема, трёхколоночный макет
- **Комментарии**: на русском
- **Именование**: Python snake_case
- **Один файл = одна ответственность** (кроме main.py — GUI + логика)
- **Оригиналы НИКОГДА не перезаписываются**
- **Консистентность замен** в рамках сеанса
- **Векторизация** для больших данных (auto_detect)
- **Threading** для длительных операций (не блокировать GUI)
- **SQLite** для хранения маппингов (не JSON файлы)
- **Версия** всегда актуальна в APP_TITLE и описании
- **Копирование текста** — все readonly textbox через `_make_readonly()`, не `state="disabled"`
